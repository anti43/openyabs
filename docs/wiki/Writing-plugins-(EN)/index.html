    Writing Plugins for OpenYaBS¶

    OpenYaBS plugins extend the application without touching the core codebase. Using a single, unified API — ExtensionContext — a plugin can add:

    • Commands (in the Plugins menu and in Search anything via Shift Shift)
    • Custom search results in Search anything
    • Settings pages (under Settings › Plugins, searchable via the settings search bar)
    • Custom tabs in the main window
    • View decorations & locks (header badges, banners with action buttons, content locks on record views)
    • Activity reactions (new/changed/deleted records, exported PDF/ODT/e-invoice files, messages)
    • Record interceptors (validate, modify, or veto saving and deleting of records)
    • Custom template placeholders ([myplugin.key] in LibreOffice .odt/.fodt templates)
    • Journal exports & tax-adviser ZIP entries (extra items in the Journal Export menu and files inside the tax-adviser ZIP)
    • Pre-send e-mail warnings (interactive confirmation or batch skip for sensitive documents)
    • E-invoice skip rules (fall back to plain PDF instead of ZUGFeRD / XRechnung for matching invoices)
    • GDPR / privacy integration (custom retention deadlines, Art. 15/20 export files, cleanup on final deletion)
    • Archived originals for locked documents (serve immutable originals and control stamped duplicates)
    • Plugin-scoped internationalization (i18n) (automatic locale resolution, MessageFormat arguments, zero key collisions)

    Plugins can be written either as a single Groovy script (.groovy, zero build step) or as a Java JAR (.jar, full IDE & build tooling). Both receive the exact same ExtensionContext API.

    How Plugins Work in OpenYaBS¶

    • Location: Plugins live in the plugins/ directory inside your YaBS application folder (Settings › Plugins › Open folder).
    • Management UI: Settings › Plugins lists every built-in, Groovy, and Java plugin with its state (RUNNING, STOPPED, DISABLED, FAILED), addition count, and error message if failed. Under Add a plugin, you can click New Groovy plugin…, Import Groovy plugin…, Import Java plugin…, or simply drag and drop a .groovy or .jar file onto the page.
    • Non-blocking startup: After login, OpenYaBS discovers plugins and compiles Groovy scripts in a background thread (yabs-plugins), showing progress in the status bar (Loading plugins (2/5): …), then calls each plugin's start(ctx) sequentially on the Swing Event Dispatch Thread (EDT).
    • Fault isolation: If a plugin throws an exception in start(ctx) or fails its minYabsVersion() check, any partial registrations are rolled back, the plugin is marked FAILED with its error message, and OpenYaBS and all other plugins continue normally.
    • Automatic cleanup & hot reload: Every contribution registered through ExtensionContext is owned by the plugin's id and automatically removed when the plugin stops, is disabled, reloaded, uninstalled, or fails to start. You can iterate and reload plugins without restarting OpenYaBS.
    • Database switching: When the user switches to or creates another database connection, OpenYaBS calls stopAll() and then startAllInBackground(). Always guard database access in start(ctx) so your plugin handles reconnects and headless test runs cleanly.
    • Plugin IDs & seamless replacement: Every plugin must have a unique, stable id(). Two plugins with the same ID never run simultaneously. Installing a new file whose plugin has the same ID as an existing file (for example, upgrading a Groovy prototype to a Java JAR) automatically stops the old plugin, activates the new one, and renames the old file to <filename>.replaced.
    • Per-plugin files on disk: Inside plugins/, OpenYaBS manages:
    • plugins.properties — comma-separated list of disabled plugin IDs
    • <safe-plugin-id>.properties — key/value store returned by ctx.settings()
    • <safe-plugin-id>/ — private directory returned by ctx.dataFolder() (created on demand)

    Groovy vs. Java: Pros, Cons, and Decision Guide¶

    Both Groovy and Java plugins have full access to ExtensionContext and all OpenYaBS classes. The difference is developer workflow, packaging, performance, and maintainability.

    Side-by-Side Comparison¶

    Aspect Groovy Plugin (.groovy) Java Plugin (.jar)
    API entry point Script variable yabs (ExtensionContext) and plugin (GroovyExtension) YabsExtension.start(ExtensionContext ctx)
    Metadata Header comments: // @id, @name, @description, @version, @author, @minYabsVersion Interface methods: id(), name(), description(), version(), author(), minYabsVersion()
    Stop hook onStop = { … } or yabs.onStop { … } stop() and/or ctx.onStop(() -> …)
    Build toolchain None — edit and save a plain text file JDK 21 + Gradle (or Maven / javac + jar)
    Reload cycle Instant (Ctrl+S in the built-in editor) Rebuild JAR → copy / import → click Reload
    Built-in editor Yes (Settings › Plugins › Edit): syntax highlighting, line numbers, F5 syntax check, snippets No — use IntelliJ IDEA, VS Code, Eclipse, or CLI + AI agent
    Type safety Dynamic typing (runtime errors for typos unless @CompileStatic is used) Full compile-time type checking and IDE refactoring
    Startup overhead Parsed and compiled by GroovyShell on every app start (noticeable for large scripts) Pre-compiled bytecode — near-instant load
    Code organization Single .groovy file (editor disables highlighting above ~60,000 chars) Unlimited packages, classes, helpers, and clean separation of concerns
    Bundled resources Not supported natively (must embed as strings or ship separate files) Native JAR resources (getResourceAsStream): .fodt templates, i18n/*.properties, JSON catalogs, icons
    Third-party libraries No @Grab (Apache Ivy is intentionally excluded from OpenYaBS); limited to JDK + bundled OpenYaBS libs Full support — bundle extra dependencies in a fat/shaded JAR if needed
    Multiple plugins per file 1 plugin per .groovy file Multiple YabsExtension implementations in one JAR (one class per line in META-INF/services/…)
    Unit testing & CI Possible via ExtensionManager.install(file), harder to unit-test internal helpers First-class JUnit 5 testing of pure logic, SQL against H2, and headless ExtensionManager
    Distribution Share one .groovy file; users can inspect/tweak directly Share one .jar file; clean versioning and reproducible builds

    Groovy Plugins — Pros & Cons¶

    Pros: - Zero setup: No JDK install, no Gradle, no IDE required — anyone running OpenYaBS can write and run a plugin in 30 seconds. - Built-in editor: Includes Groovy syntax highlighting, line numbers, working code snippets (Insert example), F5 compile check with jump-to-line error reporting, and Ctrl+S instant reload. - Concise syntax: Groovy closures automatically coerce to Java functional interfaces (Runnable, Consumer, Function, Predicate, Supplier), and dynamic property access makes quick experiments effortless. - Great for AI quick-fixes & automations: An AI agent can generate a single self-contained .groovy file that the user drops straight into plugins/ without running a build tool.

    Cons: - Runtime-only error detection: Misspelled method names or wrong argument types only fail when that code path executes. - No bundled resources: Shipping LibreOffice .fodt templates, .properties translation files, or JSON catalogs is awkward compared to a JAR. - No @Grab / external dependencies: Apache Ivy is excluded from OpenYaBS's Groovy runtime, so Groovy plugins can only use the JDK and libraries already bundled in OpenYaBS's lib/. - Does not scale well to large plugins: Startup compilation takes seconds for large scripts, single-file navigation becomes painful, and the built-in editor turns off syntax highlighting above ~60,000 characters.

    Java Plugins — Pros & Cons¶

    Pros: - Compile-time safety: The Java 21 compiler catches API mismatches, missing imports, and wrong types before the plugin ever runs. - Clean multi-class architecture: Separate persistence (Store), pure business logic (Validator), Swing UI (Ui), and entry point (Plugin), just like all official OpenYaBS plugins. - First-class resources & i18n: Bundle .fodt/.odt templates, UTF-8 messages_en.properties / messages_de.properties files, JSON data catalogs, and icons directly inside src/main/resources/. - Fast startup & high performance: Pre-compiled bytecode loads cleanly through an isolated URLClassLoader. - Full automated testing: Write fast JUnit 5 tests for validators, SQL queries (against in-memory H2), i18n bundles, and headless ExtensionManager lifecycle checks — ideal for AI coding agents running ./gradlew test in a loop! - Third-party libraries: If you need a library not shipped with OpenYaBS, you can shade/bundle it inside your plugin JAR.

    Cons: - Requires a build toolchain: Needs JDK 21 and Gradle (or Maven) to compile and package the JAR. - Slightly slower manual edit-test loop: Requires running ./gradlew jar and clicking Reload (though automated JUnit tests largely offset this).

    Decision Guide: When to Choose Which?¶

    Choose Groovy if… Choose Java if…
    You want a small automation (< ~300 lines): custom command, notification, quick search provider, simple save rule. You are building a domain/industry module (custom DB tables, dialogs, reports, exports, templates).
    You want to prototype an idea live inside OpenYaBS without setting up a build environment. You want to ship .fodt templates, multi-language .properties bundles, or data catalogs inside one JAR.
    The end user should be able to open and tweak the script directly in Settings › Plugins › Edit. You want compile-time verification, JUnit 5 tests, Git/CI workflows, or reliable distribution to many users.
    You are only using OpenYaBS's built-in classes and JDK APIs. You need third-party libraries or multiple classes/packages.

    Seamless Migration Path: Groovy → Java¶

    You can safely start in Groovy and later rewrite the plugin in Java without breaking existing installations:

    1. In your Java YabsExtension, return the exact same id() that the Groovy script used (e.g. "groovy.my-plugin" or your custom // @id).
    2. When the user installs the new .jar via Settings › Plugins › Import Java plugin…, OpenYaBS automatically stops the Groovy plugin, activates the Java plugin, and renames my-plugin.groovy to my-plugin.groovy.replaced.
    3. Because ctx.settings(), ctx.dataFolder(), and any custom database tables are keyed by id(), all user settings, files, and data are preserved seamlessly. (The official GoBD plugin uses this exact mechanism with ID = "groovy.gobd-compliance".)

    Quickstart: Groovy Plugin (30 Seconds)¶

    Option A: Using the Built-In Plugin Editor¶

    1. Open Settings › Plugins and click New Groovy plugin….
    2. Enter a name (e.g. invoice-helper). OpenYaBS creates plugins/invoice-helper.groovy from a working template and opens the Groovy Plugin Editor.
    3. Use Insert example ▾ to insert working snippets (command, search provider, activity listener, settings page, custom tab, record modifier, stored settings, background task).
    4. Press F5 (Check) to syntax-check in the background (errors jump straight to the offending line).
    5. Press Ctrl+S (Save and start) to save and immediately hot-reload the plugin. Click Other editor to edit the file in VS Code / IntelliJ / your system editor instead.

    Option B: Creating a File Directly in plugins/¶

    Create plugins/invoice-helper.groovy (UTF-8):

    // @id com.example.invoice-helper
// @name Invoice Helper
// @description Notifies on new invoices and adds a quick lookup command
// @version 1.0.0
// @author Your Name
// @minYabsVersion 2.0.10

import mpv5.db.common.Context
import mpv5.db.common.DatabaseObject
import mpv5.db.objects.Item
import mpv5.handler.Activity
import mpv5.plugin.api.SearchResult

// 1. Register a command in the "Plugins" menu and "Search anything" (Shift Shift)
yabs.addCommand('Count open invoices', 'Counts all unpaid invoices in the background', {
    yabs.background({
        def all = DatabaseObject.getObjects(Context.getInvoice())
        all.count { Item inv ->
            inv.__getIntstatus() != Item.STATUS_PAID && inv.__getIntstatus() != Item.STATUS_CANCELLED
        }
    }, { openCount ->
        yabs.notify("Open invoices: ${openCount}")
    })
})

// 2. React to newly created invoices (locale-independent via Context!)
yabs.onActivity({ Activity.Entry entry ->
    if (entry.kind == Activity.Kind.CREATED && Context.getInvoice().equals(entry.context)) {
        yabs.notify("New invoice created: ${entry.text}")
    }
})

// 3. Add custom results to "Search anything" (runs on a background thread)
yabs.addSearchProvider({ String query ->
    if (query == null || !query.toLowerCase().startsWith('open ')) {
        return []
    }
    def needle = query.substring(5).trim().toLowerCase()
    if (needle.isEmpty()) {
        return []
    }
    [new SearchResult("Search web for '${needle}'", 'Opens in default browser', {
        java.awt.Desktop.desktop.browse(new URI('https://duckduckgo.com/?q=' + URLEncoder.encode(needle, 'UTF-8')))
    } as Runnable)]
})

// 4. Optional cleanup when the plugin stops (disabled, reloaded, or app closes)
onStop = {
    // Only needed for resources you created yourself (timers, threads, sockets).
    // Commands, listeners, and providers registered via 'yabs' are removed automatically.
}

    Save the file, then click Reload in Settings › Plugins (or restart OpenYaBS).

    Groovy Plugin Details & Rules¶

    • Header tags: Must appear at the very top of the file as // @key value. Parsing stops at the first line that is neither blank nor a // comment. Keys are case-insensitive:
    • @id — stable unique ID (defaults to groovy.<filename-without-extension>)
    • @name — display name (defaults to <filename-without-extension>)
    • @description — short description (defaults to "")
    • @version — version string (defaults to "1.0")
    • @author — author name (defaults to "")
    • @minYabsVersion (aliases: @minYabs, @minVersion) — minimum OpenYaBS release version (defaults to null, i.e., any version)
    • Bound variables:
    • yabs — the ExtensionContext
    • plugin — the GroovyExtension wrapper itself
    • Returning a YabsExtension object: Instead of calling yabs.* at top level, a Groovy script may return an object implementing mpv5.plugin.api.YabsExtension. OpenYaBS will then delegate name(), description(), version(), author(), minYabsVersion(), start(ctx), and stop() to that object (note that id() is still read from @id or groovy.<filename> before execution).

    Quickstart: Java Plugin (Gradle and Java 21)¶

    1. Project Structure (Standalone Plugin Repository)¶

├── build.gradle

    2. Implement YabsExtension¶

    src/main/java/com/example/myplugin/HelloPlugin.java:

    package com.example.myplugin;

import mpv5.plugin.api.ExtensionContext;
import mpv5.plugin.api.YabsExtension;

public final class HelloPlugin implements YabsExtension {

    public static final String ID = "com.example.hello";
    private ExtensionContext ctx;

    @Override
    public String id() {
        return ID;
    }

    @Override
    public String name() {
        return ctx != null ? ctx.tr("plugin.name") : "Hello Plugin";
    }

    @Override
    public String description() {
        return ctx != null ? ctx.tr("plugin.description") : "Example Java plugin for OpenYaBS.";
    }

    @Override
    public String version() {
        return "1.0.0";
    }

    @Override
    public String author() {
        return "Your Name";
    }

    @Override
    public String minYabsVersion() {
        return "2.0.10";
    }

    @Override
    public void start(ExtensionContext yabs) throws Exception {
        this.ctx = yabs;

        ClassLoader cl = HelloPlugin.class.getClassLoader();
        yabs.addTranslationBundle("en", "/com/example/myplugin/i18n/messages_en.properties", cl);
        yabs.addTranslationBundle("de", "/com/example/myplugin/i18n/messages_de.properties", cl);

        yabs.addCommand(
                yabs.tr("cmd.greet.title"),
                yabs.tr("cmd.greet.desc"),
                () -> yabs.notify(yabs.tr("cmd.greet.msg", yabs.yabsVersion())));

        yabs.onStop(() -> {
            // Release any custom threads, timers, or connections here.
        });
    }

    @Override
    public void stop() {
        this.ctx = null;
    }
}

    3. Register via Java ServiceLoader¶

    Create src/main/resources/META-INF/services/mpv5.plugin.api.YabsExtension with one fully qualified class name per line:

    com.example.myplugin.HelloPlugin

    Note: A single JAR may list multiple YabsExtension classes (one per line). They share one URLClassLoader and are reloaded or uninstalled together. If META-INF/services/mpv5.plugin.api.YabsExtension is missing or empty, OpenYaBS rejects the JAR on import.

    4. build.gradle (Standalone)¶

    Point openyabsDir at an extracted OpenYaBS installation (containing openyabs.jar and lib/*.jar) or a local OpenYaBS build (build/libs):

    plugins {
    id 'java'
}

group = 'com.example'
version = '1.0.0'

def openyabsDir = findProperty('openyabsDir') ?: '/path/to/openyabs'

java {
    toolchain {
        languageVersion = JavaLanguageVersion.of(21)
    }
}

tasks.withType(JavaCompile).configureEach {
    options.release = 21
    options.encoding = 'UTF-8'
}

repositories {
    mavenCentral()
}

dependencies {
    compileOnly files("${openyabsDir}/openyabs.jar")
    compileOnly fileTree(dir: "${openyabsDir}/lib", include: ['*.jar'])

    testImplementation platform('org.junit:junit-bom:5.10.0')
    testImplementation 'org.junit.jupiter:junit-jupiter'
    testRuntimeOnly 'org.junit.platform:junit-platform-launcher'
    testImplementation files("${openyabsDir}/openyabs.jar")
    testImplementation fileTree(dir: "${openyabsDir}/lib", include: ['*.jar'])
}

test {
    useJUnitPlatform()
}

jar {
    archiveBaseName = 'hello-plugin'
    manifest {
        attributes(
            'Implementation-Title': 'OpenYaBS Hello Plugin',
            'Implementation-Version': project.version
        )
    }
}

    Build and install:

    ./gradlew jar

    Then install build/libs/hello-plugin-1.0.0.jar via Settings › Plugins › Import Java plugin… (or drag and drop it onto the Plugins page).

    Adding an official/in-repo plugin inside the openyabs repository: OpenYaBS's root build.gradle automatically discovers every subdirectory plugins/<name>/ that contains src/main/java! It creates a Gradle source set, compiles against OpenYaBS, wires it into src/test, and registers a <name>PluginJar task outputting build/plugins/<name>.jar (run ./gradlew pluginJars).

    Bundling third-party dependencies: If your Java plugin depends on an external library that is not already in OpenYaBS's lib/, package it into your JAR (e.g. with the Gradle Shadow plugin or by unpacking configurations.runtimeClasspath into jar), keeping openyabs.jar and lib/*.jar as compileOnly so they are never duplicated in your plugin JAR.

    Complete API Reference¶

    All public plugin API classes live in package mpv5.plugin.api (browse on GitHub).

    YabsExtension and Version Compatibility¶

    Source: mpv5.plugin.api.YabsExtension

    Method Required? Default Description
    String id() Yes — Stable unique identifier (e.g. "com.example.myplugin"). Used for deduplication, replacement, settings(), dataFolder(), and i18n scoping.
    String name() Yes — Display name shown in Plugin Manager and Plugins menu.
    String description() No "" Short 1–2 sentence summary shown in Plugin Manager.
    String version() No "1.0" Plugin version string (e.g. "1.2.0").
    String author() No "" Author or organization name.
    String minYabsVersion() No null Minimum required OpenYaBS version (e.g. "2.0.10"). null or empty means any version.
    void start(ExtensionContext ctx) throws Exception Yes — Called on the Swing EDT to initialize the plugin and register contributions. Any thrown exception marks the plugin FAILED and rolls back partial registrations.

    1. Commands, Background Work, and Custom Tabs¶

    Never block the Swing EDT with database queries, file I/O, or HTTP calls. Use ctx.background(work, then) to run slow work off-thread and update the UI safely afterward.

    Java:

    yabs.addCommand("Revenue Summary", "Opens a summary tab of this year's paid invoices", () -> {
    yabs.background(() -> {
        Object[][] rows = yabs.select(
                "SELECT cnumber, cname, netvalue, taxvalue FROM items "
                + "WHERE inttype = 0 AND intstatus = " + mpv5.db.objects.Item.STATUS_PAID
                + " ORDER BY dateadded DESC");
        return rows;
    }, rows -> {
        String[] cols = {"Number", "Title", "Net", "Tax"};
        javax.swing.JTable table = new javax.swing.JTable(rows, cols);
        table.setAutoCreateRowSorter(true);
        yabs.openTab("Paid Invoices (" + rows.length + ")", new javax.swing.JScrollPane(table));
    });
});

    Groovy:

    4. Reacting to Records and Exported Files (onActivity)¶

    Always check entry.context (locale-independent) rather than entry.detail (localized text), and always check !entry.draft before treating an exported PDF/ODT/XML as a finalized document!

    yabs.onActivity(entry -> {
    // 1. React to newly created invoices
    if (entry.kind == mpv5.handler.Activity.Kind.CREATED
            && mpv5.db.common.Context.getInvoice().equals(entry.context)) {
        yabs.notify("Created invoice #" + entry.id + ": " + entry.text);
    }

    // 2. React to issued (non-draft) exported files
    if (entry.kind == mpv5.handler.Activity.Kind.FILE
            && !entry.draft
            && entry.hasFile()
            && mpv5.db.common.Context.getInvoice().equals(entry.context)) {
        // entry.file is the exported PDF, ODT, or ZUGFeRD/XRechnung file
        // Offload heavy I/O or network upload to background():
        java.io.File exported = entry.file;
        int invoiceId = entry.id;
        yabs.background(() -> archiveCopy(invoiceId, exported),
                ok -> yabs.notify("Archived " + exported.getName()));
    }
});

    5. Validating and Vetoing Saves or Deletes (addRecordModifier)¶

    Throw new ChangeNotApprovedException(object) from modifyOnSave or modifyOnDelete to cancel the operation cleanly.

    Java:

    import java.util.Map;
import javax.swing.JOptionPane;
import mpv5.db.common.DatabaseObject;
import mpv5.db.common.DatabaseObjectModifier;
import mpv5.db.objects.Item;
import mpv5.globals.Constants;
import mpv5.ui.panels.ChangeNotApprovedException;

yabs.addRecordModifier(new DatabaseObjectModifier() {
    @Override
    public DatabaseObject modifyOnSave(DatabaseObject object) throws ChangeNotApprovedException {
        if (object instanceof Item) {
            Item item = (Item) object;
            if (item.__getInttype() == Constants.TYPE_INVOICE
                    && (item.__getDescription() == null || item.__getDescription().trim().isEmpty())) {
                int choice = JOptionPane.showConfirmDialog(
                        null,
                        "This invoice has no description. Save anyway?",
                        "Invoice Check",
                        JOptionPane.YES_NO_OPTION,
                        JOptionPane.WARNING_MESSAGE);
                if (choice != JOptionPane.YES_OPTION) {
                    throw new ChangeNotApprovedException(item);
                }
            }
        }
        return object;
    }

    @Override
    public DatabaseObject modifyOnDelete(DatabaseObject object) throws ChangeNotApprovedException {
        // Return object to allow, or throw new ChangeNotApprovedException(object) to block
        return object;
    }

    @Override public DatabaseObject modifyOnExplode(DatabaseObject object) { return object; }
    @Override public DatabaseObject executeAfterCreate(DatabaseObject object) { return object; }
    @Override public DatabaseObject executeAfterSave(DatabaseObject object) { return object; }
    @Override public Map<String, Object> modifyOnResolve(Map<String, Object> map) { return map; }
});

    7. Custom Template Placeholders (addTemplateFields)¶

    Expose custom fields from your plugin to any LibreOffice .odt or .fodt template!

    • Every entry "myplugin.fieldName" -> value in the returned map becomes usable as [myplugin.fieldName] in templates.
    • Always namespace keys with a short plugin prefix (myplugin.*) so they never collide with built-in fields (item.*, contact.*, companyinfo.*, template.*).
    • Return "" (empty string) rather than null for missing optional fields so placeholders don't remain literal [myplugin.foo] text in exported PDFs.
    yabs.addTemplateFields(obj -> {
    java.util.Map<String, Object> fields = new java.util.LinkedHashMap<>();
    if (obj instanceof mpv5.db.objects.Item) {
        mpv5.db.objects.Item item = (mpv5.db.objects.Item) obj;
        fields.put("myplugin.projectCode", loadProjectCode(item.__getIDS())); // "" if none
        fields.put("myplugin.contactRef", "C-" + item.__getContactsids());
    }
    return fields;
});

    8. Journal Export and Tax-Adviser ZIP (addJournalExport)¶

    Contribute both an interactive export format in the Journal's Export menu and automatic files inside the tax-adviser ZIP package:

    import java.io.File;
import java.nio.charset.StandardCharsets;
import java.nio.file.Files;
import java.util.Collections;
import java.util.Map;
import mpv5.handler.JournalCalc;
import mpv5.plugin.api.JournalExport;
import mpv5.plugin.api.JournalExportContext;
import mpv5.ui.dialogs.DialogForFile;

yabs.addJournalExport(new JournalExport() {
    @Override
    public String title() {
        return "Custom Accounting CSV";
    }

    @Override
    public String tooltip() {
        return "Exports counted journal entries as semicolon-separated UTF-8 CSV.";
    }

    @Override
    public void export(JournalExportContext ctx) {
        DialogForFile chooser = new DialogForFile(DialogForFile.FILES_ONLY, "custom-journal.csv");
        if (!chooser.saveFile()) {
            return;
        }
        try {
            File target = chooser.getFile();
            Files.write(target.toPath(), renderCsv(ctx).getBytes(StandardCharsets.UTF_8));
            ctx.notifyExported(target); // shows clickable file link in Journal
            yabs.notify("Exported " + target.getName());
        } catch (Exception e) {
            yabs.error("Export failed: " + e.getMessage());
        }
    }

    @Override
    public Map<String, byte[]> adviserPackageEntries(JournalExportContext ctx) {
        byte[] bytes = renderCsv(ctx).getBytes(StandardCharsets.UTF_8);
        return Collections.singletonMap("custom/journal.csv", bytes);
    }

    private String renderCsv(JournalExportContext ctx) {
        StringBuilder sb = new StringBuilder("Date;Number;Contact;Net;Tax;Gross\n");
        for (JournalCalc.Entry e : ctx.entries) {
            if (!e.counted) {
                continue;
            }
            sb.append(e.date).append(';')
              .append(e.number).append(';')
              .append(e.contact).append(';')
              .append(e.net).append(';')
              .append(e.tax).append(';')
              .append(e.gross).append('\n');
        }
        return sb.toString();
    }
});

    11. Archived Originals for Locked Records (addLockedDocumentProvider)¶

    When a plugin finalizes/locks a record with an archived PDF or e-invoice, register a LockedDocumentProvider. Whenever the user clicks Print, PDF, Preview, ODT, or E-invoice, OpenYaBS asks all providers and opens the archived original instead of regenerating the file — even if the view was not refreshed yet. If the archived file is missing on disk, OpenYaBS offers a stamped duplicate controlled by the provider:

    import java.io.File;
import java.util.List;
import mpv5.db.common.DatabaseObject;
import mpv5.plugin.api.LockedDocumentProvider;

yabs.addLockedDocumentProvider(new LockedDocumentProvider() {
    @Override
    public File lockedDocument(DatabaseObject record) {
        return findArchivedFileOrNull(record); // return File even if !file.exists()
    }

    @Override
    public String duplicateRefused(DatabaseObject record) {
        return hasTamperedData(record) ? "Record data no longer matches locked hash." : null;
    }

    @Override
    public List<String> duplicateWarnings(DatabaseObject record) {
        return findCustomerAddressDifferences(record); // user must confirm before duplicate
    }

    @Override
    public void duplicateCreated(DatabaseObject record, File missing, File duplicate) {
        logDuplicateAuditEntry(record, missing, duplicate);
    }
});

    13. Custom Database Tables and Cross-Database JDBC¶

    OpenYaBS supports H2 (default, in Derby compatibility mode), Apache Derby, MySQL / MariaDB, and PostgreSQL.

    • ctx.select(sql) and ctx.execute(sql) are convenient for quick queries, but they take plain SQL strings and swallow SQL errors.
    • For production plugins that create their own tables or accept user input, use JDBC PreparedStatement on OpenYaBS's database connection and always guard with hasDatabase() (so your plugin doesn't fail during headless tests or before DB login):
    import java.sql.Connection;
import java.sql.PreparedStatement;
import java.sql.ResultSet;
import java.sql.SQLException;
import java.sql.Statement;
import mpv5.db.common.DatabaseConnection;

public static boolean hasDatabase() {
    try {
        return DatabaseConnection.getConnector() != null
                && DatabaseConnection.getConnector().getConnection() != null;
    } catch (Throwable t) {
        return false;
    }
}

public static Connection connection() throws SQLException {
    DatabaseConnection dc = DatabaseConnection.getConnector();
    Connection c = dc == null ? null : dc.getConnection();
    if (c == null) {
        throw new SQLException("No active OpenYaBS database connection");
    }
    return c;
}

public static void initSchema(Connection conn) throws SQLException {
    // Prefix table names with your plugin short name!
    // Use portable SQL types: INT, BIGINT, VARCHAR(...), CLOB/TEXT, TIMESTAMP.
    try (Statement st = conn.createStatement()) {
        st.execute("CREATE TABLE IF NOT EXISTS myp_notes ("
                + "item_id INT PRIMARY KEY, "
                + "note VARCHAR(2000) NOT NULL, "
                + "updated_at VARCHAR(32) NOT NULL)");
    } catch (SQLException e) {
        // Apache Derby < 10.15 lacks IF NOT EXISTS (SQLState X0Y32 = table already exists)
        if (!"X0Y32".equalsIgnoreCase(e.getSQLState())) {
            throw e;
        }
    }
}

    Cross-database SQL tips: - Prefix all custom tables with a unique plugin prefix (e.g. ws_, hp_, verein_, gobd_). - Never concatenate user input into SQL — always use ? placeholders in PreparedStatement. - Do not close OpenYaBS's shared Connection! Only close your Statement, PreparedStatement, and ResultSet (via try-with-resources). - Avoid DB-specific UPSERT syntax (ON CONFLICT, MERGE, ON DUPLICATE KEY); a portable pattern is UPDATE ... WHERE id = ? and if executeUpdate() == 0, run INSERT INTO .... - Store ISO dates as VARCHAR(10) (YYYY-MM-DD) if you want identical behavior across H2, Derby, MySQL, and PostgreSQL without timezone surprises.

    Testing and Debugging Plugins¶

    Headless JUnit 5 Unit Tests (No GUI Needed!)¶

    ExtensionManager can be instantiated directly in unit tests with a temporary folder and a minimal stub Host — making it fast and reliable to test registration, commands, search providers, i18n, template fields, stop cleanup, and JAR packaging:

    import static org.junit.jupiter.api.Assertions.*;

import java.nio.file.Path;
import java.util.ArrayList;
import java.util.List;
import javax.swing.JComponent;
import mpv5.plugin.ExtensionManager;
import org.junit.jupiter.api.Test;
import org.junit.jupiter.api.io.TempDir;

class HelloPluginTest {

    @TempDir
    Path tempDir;

    static final class StubHost implements ExtensionManager.Host {
        final List<String> messages = new ArrayList<>();
        final List<String> errors = new ArrayList<>();
        @Override public void openTab(String title, JComponent content) {}
        @Override public void notify(String message) { messages.add(message); }
        @Override public void ui(Runnable r) { r.run(); }
        @Override public void changed() {}
        @Override public void error(String plugin, Throwable t) { errors.add(plugin + ": " + t); }
    }

    @Test
    void startsRegistersCommandTranslatesAndCleansUpOnStop() {
        StubHost host = new StubHost();
        ExtensionManager mgr = new ExtensionManager(tempDir.toFile(), host);

        ExtensionManager.Installed inst = mgr.register(new HelloPlugin());
        assertTrue(mgr.start(inst));
        assertEquals(ExtensionManager.State.RUNNING, inst.getState());
        assertEquals(1, mgr.commands().size());
        assertTrue(host.errors.isEmpty());

        // Test localized output across locales
        assertEquals("Hallo sagen", mgr.translateForLocale(HelloPlugin.ID, "de_DE", "cmd.greet.title", null));
        assertEquals("Say hello", mgr.translateForLocale(HelloPlugin.ID, "en", "cmd.greet.title", null));

        // Execute command
        mgr.commands().get(0).action.run();
        assertFalse(host.messages.isEmpty());

        // Stop removes all contributions
        mgr.stop(inst);
        assertEquals(0, mgr.contributions(HelloPlugin.ID));
        assertTrue(mgr.commands().isEmpty());
    }
}

    For custom SQL tables, test your Store class directly against an in-memory H2 database:

    try (Connection conn = DriverManager.getConnection("jdbc:h2:mem:plugintest;MODE=Derby;DB_CLOSE_DELAY=-1")) {
    MyPluginStore.initSchema(conn);
    // insert, query, update, assert...
}

    AI Agent Pitfalls Checklist¶

    When reviewing or prompting AI-generated plugins, watch out for these common mistakes:

    1. Wrong plugin API package: Use mpv5.plugin.api.YabsExtension + ExtensionContext, never the deprecated mpv5.pluginhandling.YabsPlugin / plugin.Main.
    2. Missing ServiceLoader file: Java JARs must contain META-INF/services/mpv5.plugin.api.YabsExtension (exact filename!) with the fully qualified class name.
    3. Header comments placed after import in Groovy: Groovy @name/@id tags are only parsed at the very top of the file before the first code/import line.
    4. Using @Grab in Groovy: Apache Ivy is excluded from OpenYaBS; @Grab will fail. Use Java + Gradle if you need extra libraries.
    5. Matching localized strings in onActivity: Check Context.getInvoice().equals(entry.context) instead of entry.detail == "Rechnung" (breaks in other UI languages).
    6. Ignoring entry.draft: Previews and intermediate PDFs emit Activity.Kind.FILE with entry.draft == true. Always skip drafts for archiving/finalization.
    7. Blocking the Swing EDT: Put slow DB queries, file exports, or HTTP requests inside ctx.background(work, then).
    8. Not guarding hasDatabase() in start(ctx): Headless tests and pre-login/DB-switch lifecycles may call start(ctx) when no DB connection is active.
    9. Closing the shared JDBC Connection: Never put DatabaseConnection.getConnector().getConnection() in a try (...) block! Closing it breaks OpenYaBS's database session.
    10. Wrong settings scope: ctx.settings() is local to one computer (plugins/<id>.properties); use GlobalSettings for business configuration shared across a multi-user database.
    11. Forgetting ChangeNotApprovedException constructor argument: Use throw new ChangeNotApprovedException(object) (it takes the DatabaseObject, not a String message — show a message via JOptionPane or ctx.error(...) first).
    12. Leaving unreplaced [myplugin.key] placeholders: Always populate every documented template key with "" when empty instead of omitting it or returning null.
