    Writing plugins for YaBS¶

    Plugins add commands, search results, settings pages, tabs, marks on record views and reactions to YaBS – in Groovy (a single file, no build) or in Java (a jar). Both get the same API: the ExtensionContext.

    • They live in the folder plugins in your YaBS folder (Settings › Plugin Manager › Open folder).
    • Settings › Plugin Manager shows every plugin with its state. There you can enable, disable, reload, edit and remove plugins, and at the top, under Add a plugin, are New Groovy plugin…, Import Groovy plugin… and Import Java plugin… side by side; you can also drop a .jar / .groovy file onto the page.
    • Commands of plugins appear in the menu Plugins and in Search anything (Shift Shift).
    • YaBS loads the plugins in the background after the start; the status bar shows the progress (Loading plugins (2/5): …). The window can be used meanwhile.
    • A plugin that fails is marked failed with its error message; YaBS and the other plugins go on.
    • Everything a plugin adds is removed again when it stops (disable, reload, remove), so a plugin can be developed and reloaded without restarting YaBS.
    • Every plugin has an id. Two plugins with the same id never run together. Installing a jar whose plugin has the id of a plugin from another file (e.g. the Java version of a Groovy script) replaces that plugin; the old file is kept as <name>.replaced.

    A plugin in Groovy – 30 seconds¶

    Settings › Plugin Manager › New Groovy plugin… creates a working plugin from a template and opens it in the plugin editor of YaBS: Groovy highlighting, line numbers, Insert example (command, search results, reacting to new records, settings page, own tab, record modifier, stored values, background work), Check (F5) shows the line of an error, Save and start (Ctrl+S) reloads the plugin at once. Edit opens existing Groovy plugins there; Other editor opens the file in your own editor. For large scripts (above about 60,000 characters) the editor switches the highlighting off so that typing stays fast – very large plugins are better written in Java.

    Or create plugins/hello.groovy yourself:

    // @name Hello
// @description Says hello and notices new invoices
// @version 1.0
// @author You
// @minYabsVersion 2.0.10

// a command: menu "Plugins" and Search anything
yabs.addCommand('Say hello', 'A first command', {
    yabs.notify('Hello from Groovy!')
})

// react to new records (and created files, changed and deleted records)
yabs.onActivity({ entry ->
    if (entry.kind == mpv5.handler.Activity.Kind.CREATED && entry.detail == 'Rechnung') {
        yabs.notify('New invoice: ' + entry.text)
    }
})

// results in Search anything
yabs.addSearchProvider({ text ->
    text == 'weather' ? [new mpv5.plugin.api.SearchResult('Open the weather', 'wttr.in', {
        java.awt.Desktop.desktop.browse(new URI('https://wttr.in'))
    })] : []
})

// called when the plugin stops (the same as yabs.onStop { ... })
onStop = { }

    Save, then click Reload in the Plugin Manager – done.

    • The comment lines at the top (// @name, @description, @version, @author, @id, @minYabsVersion) describe the plugin; the id defaults to groovy.<file name>.
    • The script runs when the plugin starts, with yabs bound to the ExtensionContext and plugin to the plugin itself. Closures work wherever the API expects a function.
    • A script may also return an object that implements YabsExtension – then that object is the plugin.

    A plugin in Java¶

    1. Implement mpv5.plugin.api.YabsExtension:
    package com.example;

import mpv5.plugin.api.ExtensionContext;
import mpv5.plugin.api.YabsExtension;

public class Hello implements YabsExtension {
    public String id()             { return "com.example.hello"; }
    public String name()           { return "Hello"; }
    public String description()    { return "Says hello"; }
    public String minYabsVersion() { return "2.0.10"; }

    public void start(ExtensionContext ctx) {
        ctx.addCommand("Say hello", "A first command", () -> ctx.notify("Hello!"));
        ctx.onStop(() -> { /* close what the plugin opened itself */ });
    }
}
    1. List the class in META-INF/services/mpv5.plugin.api.YabsExtension (one class per line – a jar may contain several plugins):
    com.example.Hello
    1. Compile against openyabs.jar (and lib/* if you use them), build a jar, put it into plugins or install it in the Plugin Manager.

    A minimal build.gradle:

    plugins { id 'java' }
dependencies { compileOnly files('/path/to/openyabs/openyabs.jar') }
java { toolchain { languageVersion = JavaLanguageVersion.of(21) } }

    Groovy and Java side by side¶

    Groovy Java
    The API yabs (the ExtensionContext) the ctx passed to start
    Id, name, description, version, author // @id, // @name, // @description, // @version, // @author id(), name(), description(), version(), author()
    Minimum YaBS version // @minYabsVersion 2.0.10 minYabsVersion()
    Start the script runs start(ctx)
    Stop onStop = { … } or yabs.onStop { … } stop() or ctx.onStop(() -> …)
    Functions closures { x -> … } lambdas x -> …
    Distribution one .groovy file a .jar with META-INF/services/mpv5.plugin.api.YabsExtension

    What the context offers¶

    Contributions (removed again when the plugin stops)¶

    Method What it does
    addCommand(title, description, action) a command in the menu Plugins and in Search anything (runs on the Swing thread)
    addSearchProvider(text -> List<SearchResult>) results in Search anything (runs in the background; keep it quick). new SearchResult(title, detail, () -> …)
    addSettingsPage(title, description, () -> JComponent) a page in Settings (group Plugins), found by the settings search
    onActivity(entry -> …) told about created / changed / deleted records, created files (PDF, ODT, e-invoices) and messages – see Activity.Entry: kind, text, detail, file, context, id (Swing thread)
    addRecordModifier(DatabaseObjectModifier) take part when records are saved, created, deleted: modifyOnSave, modifyOnDelete (throw ChangeNotApprovedException to stop the change), executeAfterCreate, executeAfterSave, modifyOnExplode, modifyOnResolve
    onView(view -> …) told when a record view (DataPanel) is opened or shows another record, also for views open when the plugin starts – see Record views below
    onStop(() -> …) runs when the plugin stops, is disabled, reloaded or fails to start
    addLockedDocumentProvider(LockedDocumentProvider) names the archived original of locked records: lockedDocument(record) returns the file (also if it is missing) or null. Print, PDF, preview, ODT and e-invoice open it instead of creating a new file; YaBS asks on every click. If the file is missing, YaBS offers a stamped duplicate: duplicateRefused, duplicateWarnings and duplicateCreated let the plugin refuse it, name differences and record it (example: GoBD plugin, The archived original)

    Actions and helpers¶

    Method What it does
    openTab(title, component) opens a tab in the main window
    notify(message) a message in the status bar and the activity list
    popup(message) / error(message) a notification pop-up (and the activity list)
    notify(message, record) a pop-up about a record, logged with the record (a click opens it)
    select(sql) runs a SELECT on the YaBS database, returns Object[][] (never null)
    execute(sql) runs a statement (CREATE TABLE, INSERT, UPDATE …)
    ui(() -> …) runs code on the Swing thread (now if already there)
    background(work, then) runs work in the background and continues on the Swing thread with the result; errors are reported
    currentView() the record view of the selected tab, or null
    refreshView(record) shows the record again in every open view that shows it (e.g. after the plugin changed or locked it)
    openFile(file) opens a file with its program (PDFs: the PDF viewer of Settings › External programs)
    settings() key/value settings of the plugin, stored on this computer: get, set, getBoolean, setBoolean
    dataFolder() a folder for the plugin's own files
    yabsVersion() the version of YaBS

    select and execute take plain SQL: put user input into a query only escaped (' doubled), or use the normal YaBS classes.

    Record views¶

    In onView, a plugin can mark the view (mpv5.ui.panels.DataPanel); YaBS clears these marks before it calls the plugins again:

    Method of the view What it does
    getDataOwner() the record shown (Item, Contact, Product, Expense, Revenue …)
    setPluginBadge(component) a small mark in the header of the view, next to the status
    setPluginBanner(component) a banner below the command bar, e.g. with buttons
    setContentLocked(true) locks the content fields and positions (payment status, reminders, export stay usable)
    setLockedDocument(file) for a locked record: print, PDF, preview, ODT and e-invoice open this archived file instead of creating a new one. addLockedDocumentProvider is more reliable: the mark of the view is missing as long as the view was not shown again
    setDataOwner(record, true) shows a record (again) 
    yabs.onView({ view ->
    def r = view.getDataOwner()
    if (r instanceof mpv5.db.objects.Item && r.__getIntstatus() == mpv5.db.objects.Item.STATUS_PAID) {
        view.setPluginBadge(new javax.swing.JLabel('paid'))
    }
})

    Threads¶

    start, stop, commands, onActivity, onView and the second part of background run on the Swing thread – keep them short and use background for database work that takes long. Search providers run in the background. A plugin only needs stop() / onStop for what it created itself (threads, timers, connections) – everything registered through the context is removed by YaBS.

    Records, contexts and queries are the normal YaBS classes (mpv5.db.common.DatabaseObject, Context, QueryHandler, …); the Groovy console (Settings › GroovyConsole) is a good place to try things out.

    Examples¶

    • The Activity journal (source) ships with YaBS: it writes created files and records to a CSV journal, makes the journal searchable in Search anything, and offers a command and a settings page. You can disable it like any other plugin.
    • The GoBD plugin (source, documentation) is a large Java plugin: record modifier, onActivity, onView with badges, banners and locks, commands, a settings page, a tab, search results, its own database tables and a timer. It comes as plugins/gobd-compliance.jar with YaBS.

    Classic plugins¶

    Plugins of older YaBS versions (a class plugin.Main implementing mpv5.pluginhandling.YabsPlugin, stored in the database) still work; they are listed at the bottom of the Plugin Manager under Classic plugins (database) (click Show).
